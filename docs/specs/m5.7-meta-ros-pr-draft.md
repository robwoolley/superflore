## Suggested body

```markdown
## Summary

Regenerates recipes with a fixed superflore
(ros-infrastructure/superflore#<PR-NUMBER>) that computes the transitive
closure of REP-149 `build_export_depend`/`buildtool_export_depend` tags,
instead of relying on bitbake's own sysroot staging to propagate them
(which it only does for target-space exports reached through target
dependencies — a native dependency of a target dependency was silently
dropped). Full design writeup:
[`docs/specs/bitbake-export-depends.md`](<link once merged>) in that PR.

**What changed in generated output**, additively:
- Two new variables per recipe, `ROS_TRANSITIVE_EXPORT_DEPENDS` and
  `ROS_TRANSITIVE_BUILDTOOL_EXPORT_DEPENDS`, folded into `DEPENDS`.
  Nothing existing changes meaning; layers reading `ROS_EXPORT_DEPENDS`/
  `ROS_BUILDTOOL_EXPORT_DEPENDS` are unaffected.
- `ROS_SUPERFLORE_GENERATED_BUILDTOOLS_<DISTRO>` (feeding
  `ros_superflore_generated.bbclass`'s `BBCLASSEXTEND` gate — see below)
  now includes packages reached only *transitively* as a `-native`
  dependency, not just direct `<buildtool_depend>`/`<buildtool_export_depend>`
  tags. This is the actual fix for the `Nothing PROVIDES '<pkg>-native'`
  class of failure.
- The `ament_cmake` special case in `yocto_recipe.py` (which hard-coded
  blanking its `ROS_EXPORT_DEPENDS` and manually native-resolving it) is
  gone — the general closure produces a superset of what it did.

**For `ros_superflore_generated.bbclass` reviewers specifically:** the
`BBCLASSEXTEND` gate itself
(`bb.utils.contains('ROS_SUPERFLORE_GENERATED_BUILDTOOLS', '${BPN}-native', ...)`)
is unchanged — only what feeds `ROS_SUPERFLORE_GENERATED_BUILDTOOLS` grew,
per the design note. No bbclass changes are needed or included here.

## Why

Metapackages whose entire purpose is exporting a dependency set
(`ament_cmake`, `rosidl_default_generators`, `rosidl_core_generators`, …)
were not delivering that set to consumers, because bitbake has no "export"
concept and RSS-era sysroot staging prunes exactly the edge REP-149's
buildtool export tags rely on (native dependency of a target dependency).
Downstream integrators have been papering over this with hand-written
`.bbappend` files for years — see the corpus at
[`docs/specs/corpus/`](<link>) (935 such bbappends found in this repo alone,
64% of a representative sample explained by this fix).
```
